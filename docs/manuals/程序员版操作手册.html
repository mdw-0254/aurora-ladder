1 项目概览

先搞清楚整体结构

Aurora 采用 Electron 主进程 / 渲染进程分离架构。渲染层（Vue 3）通过 preload 暴露的 contextBridge 与主进程进行 IPC 通信；代理能力由主进程内的纯 Node.js 正向代理模块实现，不依赖任何第三方代理内核。

分层技术职责
渲染层Vue 3 + Vite六个页面：总览 / 服务器 / 连接 / 日志 / 设置 / 关于
桥接层preloadcontextBridge 暴露受限 API（window.aurora.*）
主进程Electron + Node.js状态机、正向代理、SS 加密客户端、系统代理、订阅解析、天气、设置持久化
网络层HTTP / HTTPS本地监听 127.0.0.1:7891，接管系统代理流量

3 从源码运行

环境与常用命令

环境要求：Windows 10 / 11（x64）、Node.js 18+ 与 npm。

npm install                        # 安装依赖
npm run dev                        # 开发模式：构建渲染层并启动应用
npm run build                      # 仅构建渲染层（输出到 dist/）
npm run start                      # 直接启动（跳过构建）
npm run dist                       # 打包单文件便携版（自动先 vite build）
npm run dist:installer             # 打包 NSIS 安装版

国内环境如遇 Electron 下载缓慢，可在项目根目录新建 .npmrc：

electron_mirror=https://npmmirror.com/mirrors/electron/

5 核心配置

运行参数与行为开关
  • 代理端口：默认 7891，可在「设置」中修改，重连后生效。
  • 系统代理：连接时写入注册表，断开时自动恢复。
  • 主题：深色（紫青科技风）/ 浅色（央视红金白），由 src/styles/main.css 的 CSS 变量驱动，全局自适应。
  • 订阅批次：每次导入独立成批，可整批删除；旧节点自动归入「历史导入」；重复导入同一订阅只刷新配置不破坏批次。
  • 更新检查：启动后延时约 3 秒自动检查 +「关于」页手动检查，基于 GitHub Releases。

6 协议支持

解析与直连的范围
能力范围
订阅解析vmess / vless / ss / ssr / trojan / hysteria2 / tuic / wireguard / Clash YAML
真实连接完整支持 Shadowsocks（SS）加密隧道转发
其它协议仅可导入与管理，连接时提示「暂不支持直连」

SS 客户端已处理 TCP 分包导致的解密 nonce 错位问题，兼容大流量 HTTPS 页面（如大型网站）加载。

7 二次开发要点

常用改动入口
  • 渲染层调用主进程：通过 window.aurora.*（IPC），新增能力需在 main.js 注册 ipcMain.handle 并在 preload.js 暴露。
  • 设计系统：改配色在 src/styles/main.css（:root 与 [data-theme='light'] 两组变量）。
  • 新增页面：在 src/pages/ 建组件，并在 Sidebar.vue 的 navs 数组注册。
  • 代理逻辑：入口 electron/proxy-server.js，SS 加解密在 electron/ss-client.js。
  • 订阅解析：新增协议解析逻辑集中在 electron/subscription.js。

8 打包发布

从版本号到用户可下载
1
改版本号：更新 package.json 的 version 字段。
2
打包：npm run dist 生成 portable.exe；npm run dist:installer 生成安装版。
3
创建 Release：在 GitHub 仓库 Releases 新建，tag 填 v1.0.1（带 v 前缀、与 version 数字一致），上传 .exe 附件。
4
配置更新仓库：在 main.js 顶部设置 UPDATE_OWNER / UPDATE_REPO，未配置时更新检查自动停用。
注意：便携版不支持 electron-updater 静默升级，采用"版本检查 + 手动下载"方案，发布后用户下次启动 / 手动检查即可收到提示。

9 调试与验证

日志、冒烟测试与排错
  • 日志：应用内「日志」页可查看启动、连接、代理事件；主进程日志走 console。
  • 冒烟测试：设置环境变量 AURORA_SMOKE=1 启动，应用会自动"连接 → 观察 → 断开 → 退出"，用于验证真实隧道与速率统计。
  • 端口占用：启动失败先检查 7891 是否被占用，Get-Process | Where-Object { $_.ProcessName -like '*Aurora*' } | Stop-Process -Force 清理残留进程。
  • 系统代理残留：异常退出后若代理未恢复，手动到 Windows 设置 → 网络 → 代理，关闭手动代理即可。

10 常见问题

开发与部署中常见的坑
Q 打包出的 exe 被 Windows 提示风险？
软件未购买代码签名证书，属正常现象。可引导用户点"更多信息 → 仍要运行"，或将 exe 加入信任。
Q SS 节点连上但大网页加载失败？
通常是加解密 nonce 错位（TCP 分包），本仓库 ss-client.js 已处理；若改过该文件请回归验证。
Q 更新检查不生效？
确认 main.js 的 UPDATE_OWNER / UPDATE_REPO 已配置且 GitHub 有对应 Release。
Q 如何在双平台同步？
本仓库配置了 origin（GitHub）与 gitee 两个远程，推送时分别 git push origin main 与 git push gitee main。
